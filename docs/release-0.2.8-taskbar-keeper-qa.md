# v0.2.8 작업표시줄 유지 모듈 배포 검증

## 배포 범위

정상 동작을 확인한 v0.2.8 실행 파일과 외부 유지 방식을 보존합니다. 기존 v0.2.8 태그, 설치 파일, 서명, 업데이트 manifest는 그대로 두고 유지 모듈 ZIP을 추가합니다. 앱 소스는 수정하거나 재빌드하지 않습니다.

이전에 실패한 `taskbar_window.rs` 실험 수정은 로컬 작업 폴더에 보존하며 이번 커밋과 공개 배포에는 포함하지 않습니다. 기존 생성 스키마와 개인 프롬프트도 포함하지 않습니다.

## 확인한 결과

- 볼륨 메뉴를 열었다 닫은 뒤 숫자가 계속 보인다는 사용자 확인을 받았습니다.
- 정상 앱 실행 파일 SHA-256: `A67DC7BA19B5F245EC23C8450899093438F5DDCDF2A7E8FEA982A7F2007C8C20`.
- 원래 유지 모듈 SHA-256: `FD767139AEEB531D5256D7429C3CCD66059C8ADC9A4A3962E882E9C52479383D`.
- 로그인 자동 실행 작업이 활성화되어 실제 Running 상태이며, 설정 전후 앱 PID가 같았습니다.
- 추적 파일 120개의 해시를 비교해 자동 실행 설정 과정에서 프로젝트 파일이 바뀌지 않았음을 확인했습니다.
- 배터리 사용 중에도 시작·유지하며 시간 제한 없이 실행하고 중복 작업은 시작하지 않도록 설정했습니다.
- 공개 배포용 유지 모듈은 설치 경로 한 줄만 현재 사용자의 `LOCALAPPDATA`로 치환했습니다. Win32 코드와 반복 동작은 같습니다.
- 공개 사본 SHA-256: `03CC3025F1294C7F240845382ABEF56BC5EE9A632E4509164C2106C7F442A3BB`.
- 현재 PC에 설치된 원본 유지 모듈은 공개 사본으로 교체하지 않았습니다.
- 배포용 PowerShell 스크립트 3개의 구문 검증을 통과했고 개인 사용자 경로가 포함되지 않았음을 확인했습니다.
- 릴리스 테스트 5개와 `npm run verify:release`, `git diff --check`를 통과했습니다.

## 미검증

실제 재부팅과 다른 PC 새 설치는 수행하지 않았습니다. 앱 내부 실험 수정의 테스트 통과는 이 배포물의 실제 메뉴 검증 근거로 사용하지 않습니다.
