# SPECTRA 디자인·실행 용량 개선 계획

> 작성: 2026-09-04 · 기준 커밋 `feabeed` · 상태: 승인(2026-09-04, 권장안 4개 채택) · Phase 0·1 완료 · Phase 2 구현 완료(2026-09-05, 기준선 rev 3 · 메모리 측정 대기) · Phase 3 대기
> 목표: "한눈에 봐도 좋은 디자인"과 "트레이 상주 앱다운 작은 실행 용량"을 동시에 달성한다. 두 목표가 충돌하는 지점은 디자인 원칙(`docs/design-baseline/README.md`)을 기준으로 판정한다.

## 1. 성공 기준 (체크 가능 형식)

| 축 | 기준 | 측정 방법 |
|---|---|---|
| 디자인 | 미니 창(430×720)을 열면 2초 안에 "지금 어느 서비스에서 작업할지"가 첫 화면 상단에 문장으로 보인다 | 기준 스크린샷 + 수동 확인 |
| 디자인 | 네이티브 앱에서 실제 데이터가 아닌 숫자·그래프가 한 개도 남지 않는다 | `source === "example"` 렌더 경로 검색 |
| 디자인 | `backdrop-filter`를 쓰는 표면이 내비게이션 1곳 + 대화상자 1곳뿐이다 | `grep -c backdrop-filter styles.css` ≤ 4 (prefix 포함) |
| 디자인 | 라이트 테마에서 하드코딩된 `#fff`·`rgba(255,255,255…)`가 토큰으로 대체된다 | `verify:tokens` 확장 |
| 용량 | 제품 CSS가 제품에서 쓰지 않는 B 시안·시안 전환기 규칙을 포함하지 않는다 | `dist/*.css`에 `orbit-`·`prototype-switcher` 0건 |
| 용량 | 글꼴 파일 수 4 → 3 이하, 합계 ≤ 810 KB | `dist/assets/*.woff2` 합산 |
| 용량 | JS 번들 ≤ 240 KB(React 유지) 또는 ≤ 120 KB(Preact 전환 승인 시) | `verify:memory` 임계값 하향 |
| 용량 | 기본 빌드 실행 파일이 `keyring`·`uuid`·`sha2`·`base64`를 링크하지 않는다(`reqwest`는 Claude 조회용으로 유지) | `cargo tree` + 실행 파일 크기 7.57 MB → 측정 후 목표 확정(예상 6.5 MB 내외) |
| 용량 | 미니 창 표시 후 30분 idle 작업 집합(호스트 + WebView2 전체) 441 MB → ≤ 380 MB | `scripts/measure-memory.ps1` |
| 용량 | (선택) 트레이 대기 모드에서 전체 작업 집합 ≤ 60 MB | 동일 스크립트 |

## 2. 현황 진단

### 2-1. 실행 용량 수치 (2026-08-23 빌드 기준)

| 항목 | 현재 | 원인 |
|---|---|---|
| JS 번들 | 230.7 KB | React 19 + react-dom (앱 코드는 ≈ 45 KB 추정) |
| CSS 번들 | 42.7 KB | B 시안(orbit) ≈ 7.4 KB, 시안 전환기, 미디어 쿼리 안 B 규칙까지 제품 번들에 포함 |

### 2-3. 디자인 진단 (기준 스크린샷 `desktop-a.png` 기준)

| 항목 | 현재 | 문제 |
|---|---|---|

| 라이트 테마 | 흰색 하드코딩 잔여 (2026-08-16 검토) | 토큰 체계 불완전 |
| 미니 창 | 430×720에서는 C(모바일) 시안이 마운트 | 데스크톱 트레이 위젯에 모바일 하단 내비게이션·날짜 헤더가 그대로 보임 — 별도 "미니" 밀도가 없음 |

## 3. 설계 원칙 (이번 개선에서 고정)

1. **답부터 보여준다** — 첫 화면 최상단은 장식 문장이 아니라 "다음 행동" 한 줄이다.
2. **없는 데이터는 그리지 않는다** — 네이티브 앱에서 예시 그래프·스파크라인·데모 배지를 없앤다. 현재 스냅샷만으로 계산 가능한 지표(잔여·시간 진행·속도)만 시각화한다.
3. **유리는 두 곳만** — 내비게이션 레일과 OAuth 대화상자 배경. 나머지 표면은 불투명 토큰 + 1px 상단 하이라이트로 깊이를 만든다.
4. **배경은 그라디언트 한 장** — 블러 필터·SVG 노이즈 없이 `radial-gradient` 겹침으로 같은 분위기를 낸다.
5. **굵기 3단** — 400·600·700. 650·750·800·900 요청을 CSS에서 제거해 합성 굵기 계산을 없앤다.
6. **실행 파일은 쓰는 것만 링크** — 미래용 OAuth 경로(`keyring`·`uuid`·`sha2`·`base64`)는 cargo feature 뒤로. `reqwest`는 Claude 조회에 쓰이므로 유지.
7. **측정 없이는 완료 선언 없음** — 각 단계는 `measure-memory.ps1` 전후 수치를 문서에 남긴다.

## 4. 단계별 계획

순서는 "측정 도구 → 비용 0의 제거 → 디자인 재구성 → 네이티브 슬림화 → 선택형 대기 모드"다. 각 단계는 독립 커밋·독립 측정이 가능하다.

### Phase 0 — 측정 기반 마련 (선행, 0.5세션)

| 항목 | 내용 | 파일 |
|---|---|---|
| 메모리 측정 스크립트 | `spectra-native` PID와 부모 PID가 일치하는 `msedgewebview2` 프로세스를 모아 WorkingSet·PrivateBytes 합계를 CSV로 남김. 인자: 시나리오 이름, 샘플 간격, 횟수 | `scripts/measure-memory.ps1` (신규) |
| 번들 리포트 | `dist/assets` 파일별 크기와 gzip 크기 출력. `verify:memory`에 CSS·글꼴 임계값 추가 | `scripts/verify-memory-budget.mjs` 확장 |
| 기준 수치 기록 | 현재 빌드로 미니·대시보드·트레이 숨김 3시나리오 × 30분 측정 후 표로 기록 | `docs/performance/memory-budget.md` |

성공 기준: 3시나리오 기준 수치가 문서에 있고, `npm run verify:memory`가 CSS·글꼴 크기까지 검사한다.

### Phase 1 — 비용 0의 제거 (디자인 변화 없음, 0.5세션)

| 항목 | 변경 | 예상 효과 |
|---|---|---|
| B 시안·시안 전환기 CSS 분리 | `styles.css`에서 `orbit-*`·`prototype-*`·`.stream-header .widget-lab` 등 프로토타입 전용 규칙을 `styles/prototype.css`로 이동. `app.js` 기준선은 이 파일을 별도로 로드 | CSS 42.7 → ≈ 30 KB |
| `drift` 키프레임 삭제 | 적용처 없음 | 죽은 코드 제거 |
| Medium 글꼴 제거 | `@font-face` 500 삭제, `font-weight: 500` 사용처 없음 확인 | 글꼴 1,075 → 806 KB |
| 굵기 정규화 | 650→600, 750·800·900→700으로 치환 | 합성 굵기 계산 제거 |
| 인라인 SVG 그레인 제거 | `.grain` 삭제 | 노이즈 래스터 제거 |

성공 기준: `verify:baseline`·`verify:tokens` 통과, 스크린샷 육안 차이 없음(그레인 opacity .018은 식별 불가 수준), Phase 0 측정 대비 작업 집합 감소 기록.

### Phase 2 — 디자인 재구성 (핵심, 1.5세션)

#### 2-A. "다음 행동" 스트립 (헤드라인 대체)

- 위치: 헤더의 대형 h1 자리. 높이는 현재의 절반 이하.
- 내용: 스냅샷만으로 계산하는 문장 1개 + 근거 칩 2개.
  - 예) **지금은 Claude에서 작업** · Codex 5시간 한도 24% 남음, 1시간 18분 후 초기화 · Claude 5시간 한도 32% 남음
- 판정 규칙(`src/data/next-action.ts` 신규, 순수 함수): 가장 짧은 창의 잔여율이 높은 공급자를 권장. 동률이면 초기화가 늦은 쪽. 연결 안 된 공급자는 "연결 필요"로 별도 문장.
- 미연결 상태에서는 "Codex 연결 후 권장 서비스를 알려 드립니다"로 대체. 예시 수치는 쓰지 않는다.
- 구현 확정(2026-09-05): 스트립 높이는 기존 헤드라인의 약 58%로 확정(24px 헤드라인 + 칩 1행).

#### 2-B. 쿼터 셀에 "시간 진행" 두 번째 트랙

- 창 시작·초기화 시각으로 시간 진행률을 계산해 얇은 두 번째 바(또는 같은 바의 눈금 마커)로 표시.
- 사용률 > 시간 진행률이면 "빠름", 그 반대면 "여유" 라벨을 텍스트로 병기(색만으로 상태 구분 금지).
- 이 계산은 기존 `QuotaWindow`에 `windowStartedAt`가 있어야 한다. 백엔드 응답에 창 길이(5h/7d)가 있으므로 `resetAt − duration`으로 파생 가능 — `provider_usage.rs` 수정 없이 프론트에서 계산.
- 구현 확정(2026-09-05): 사용률과 시간 진행률의 차이가 10p 이내면 라벨을 생략하고, 초기화 시각이 지난 창에는 트랙을 표시하지 않는다.

#### 2-C. 예시 그래프 제거·대체

- 개요의 "한도 소진 추이" 막대 차트와 집중 확인 카드의 스파크라인은 네이티브 빌드에서 제거.
- 대체: "창 요약" 패널 — 공급자별 4개 창을 시간 진행 vs 사용률 2축 점으로 표시하는 정적 SVG(요소 4개, 애니메이션 없음). 브라우저 데모에서만 예시 데이터 허용.
- `Sparkline.tsx`·`usageBars`는 데모 전용으로 분기하거나 삭제.
- 구현 확정(2026-09-05): 점 최대 4개에 "사용률 = 시간 진행률" 기준선 1개를 더한 정적 SVG.

#### 2-D. 표면·배경 체계 정리

- `app-surface`·`glass-card`에서 `backdrop-filter` 제거, `--color-surface-*` 불투명 토큰 + `--shadow-inset` 하이라이트로 대체.
- 그림자 블러 반경 54px·34px → 24px·16px로 축소하고 카드 그림자를 2단으로 통일.
- `.ambient`: 오브 3개 삭제, `radial-gradient` 2~3겹을 `background-image`로 합성(필터 없음).
- `--glass-*` 토큰은 `nav-rail`·`oauth-backdrop`만 유지.

#### 2-E. 미니 창 전용 밀도

- 브레이크포인트를 뷰포트 폭만이 아니라 Tauri 창 모드(`mini`/`dashboard`)로도 판정. 미니 모드에서는 C 시안의 날짜 헤더·하단 내비게이션 대신 상단 2-A 스트립 + 쿼터 보드 4셀 + 새로고침만 남긴다.
- 창 모드는 `desktop_shell.rs`의 `WindowMode`를 `window.__SPECTRA_MODE__` 또는 URL 쿼리로 전달.

#### 2-F. 라이트 테마 마무리

- 2026-08-16 검토에서 남은 흰색 하드코딩을 토큰으로 치환. `verify:tokens`에 `#fff`·`rgba(255,255,255` 직접 사용 검사 추가.

성공 기준: 기준 스크린샷 3장 재촬영·`baseline.json` 갱신, `backdrop-filter` ≤ 4건, 네이티브 빌드에서 `source === "example"` 렌더 경로 0건, Phase 1 대비 작업 집합 추가 감소 기록.

### Phase 3 — 네이티브 슬림화 (1세션)

| 항목 | 변경 | 예상 효과 |
|---|---|---|
| OAuth 경로 feature 게이트 | `Cargo.toml`에 `native-oauth` feature(기본 off). `keyring`·`uuid`·`sha2`·`base64`를 optional로, `oauth_callback.rs`·`credential_vault.rs`·`provider_connection.rs`를 `#[cfg(feature = "native-oauth")]`로 감쌈. `reqwest`는 `provider_usage.rs`의 Claude 조회에 필요하므로 유지. 프론트 `oauth-adapter.ts`는 feature 없을 때 "준비 중" 상태 반환 | 실행 파일 7.57 → 측정 후 확정(keyring·sha2 제거분), 설치 파일 소폭 감소 |
| `withGlobalTauri` | 프론트가 `@tauri-apps/api` 없이 `window.__TAURI__`를 직접 쓰므로(`tauri-native-bridge.ts`) 현행 유지. 끄려면 `@tauri-apps/api` 의존성이 추가되어 번들이 커지므로 변경하지 않음 | 변경 없음 |
| WebView2 추가 인자 | `additional_browser_args`에 `--disable-features=msSmartScreenProtection,msWebOOUI,msPdfOOUI` 유지 + `--renderer-process-limit=1`. `--disable-gpu`·single-process는 사용하지 않음(기존 결정 유지) | 프로세스 수 7 → 5~6 (측정 후 확정) |
| 릴리스 프로필 | 현행(opt-level s, thin LTO, strip) 유지. `lto = "fat"` 비교 측정 1회 | 수십 KB 수준, 측정 후 채택 여부 결정 |

성공 기준: 기본 빌드 `cargo tree`에 `keyring`·`sha2`·`base64` 없음, 실행 파일 크기 전후 수치 기록, 기존 Codex·Claude 연결 QA 재통과.

### Phase 4 — 선택형 저메모리 대기 모드 (승인 후, 1세션)

- 동작: 창 닫기(트레이 숨김) 시 WebView 창을 `destroy`, 트레이 클릭 시 `WebviewWindowBuilder`로 재생성. 설정에서 "빠른 재표시(기본)" / "메모리 절약" 중 선택.
- 상태 복원: 테마·창 모드·마지막 스냅샷은 Rust 측 `AppState`에 보관하고 재생성 시 초기 URL 쿼리로 전달. `localStorage` 금지 원칙 유지.
- 예상: 대기 중 작업 집합 ≈ 35~60 MB. 재표시 지연 300~600 ms.
- 함께 검토: 트레이 아이콘에 최소 잔여율을 숫자로 그려 넣기(`build.rs`의 `png` 인코더 재사용). 창을 열지 않아도 잔여량을 볼 수 있어 대기 모드의 체감 지연을 상쇄한다. 갱신은 시작 시·수동 새로고침 시에만(폴링 금지 원칙 유지).

성공 기준: 대기 모드 30분 작업 집합 ≤ 60 MB, 재표시 후 테마·모드가 유지됨, 기본값은 현행 동작.

## 6. 가정

- 디자인 방향은 A(데스크톱)·C(모바일) 기준선을 유지하고 "재구성"하며, 새 시안을 만들지 않는다.
- 브라우저 프로토타입(`app.js`, B 시안)은 기준선으로 보존하되 제품 번들에서 분리한다.
- 메모리 예산 문서의 금지 항목(폴링·`localStorage`·차트 라이브러리·`requestAnimationFrame`)은 그대로 유지한다.
- macOS·iOS(PLAN.md 5단계)는 이번 범위 밖이다.
